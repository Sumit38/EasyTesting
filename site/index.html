What is EasyTesting?

A simple way to check your website works

Every website changes all the time, and every change can break something. Testing is how you find out before your users do. EasyTesting does the slow parts of testing for you: it writes the checks, runs them in a real browser, and tells you in plain language what passed, what failed, and how much to trust the answer.

Testing without it
  • Writing test cases takes days. Someone has to think of every case and type out every step by hand.
  • Tests break when the page changes. Rename a button and every test that clicks it fails, even though nothing is wrong.
  • Results are hard to trust. A green tick doesn't say what was never tested, or whether a failure is a real bug.
  • You need to know how to code to automate anything.
With EasyTesting
  • Describe it, get the cases. Paste a use case in plain words and download ready-to-use test cases as Excel.
  • Tests find their way again. A renamed or moved button is found again, and you see exactly what changed.
  • Every result says how sure it is. Plus what was covered, what wasn't, and a clear risk score.
  • No code. Everything is plain English in your browser. Existing Playwright and Selenium tests work too.

In plain words

The few terms you'll see

Testing has a lot of jargon. Here is all you need, in everyday language.

Use case
A short description of something a person does with your app, such as “signing in”.
Test case
A checklist for one situation: the steps to follow and what should happen at the end.
Locator
How a test points at a button or field on the page. When the page changes, old locators stop working.
Self-healing
The test notices the change and finds the button or field again, instead of failing.
Confidence score
How sure EasyTesting is that it understood a step and ran it right. Higher is better.
Residual risk
A 0 to 100 score for how risky a release still is after testing. Lower is better.

How it works

No scripts, no setup of test tools, nothing to install on your app.

A use case, an Excel sheet of test cases, or an existing test project. Start wherever you are.

2

Self-healing

The page changed. The test didn't fail.

A developer renames a button, wraps it in a new box, or changes its id. Normally every test that touches it stops with “element not found”. EasyTesting remembers what the element looked like and finds it again.

  • Shows you what changed. The old locator beside the new one, with how sure it is.
  • Refuses to guess. If a button is renamed beyond recognition, it stops and lists what's on the page instead of clicking the wrong thing.
  • You decide what's saved. Nothing is written into your tests until you press Apply.

Questions

Frequently asked

Do I need to know how to code?

No. Use cases and test cases are plain English, and you work in the browser. If you already have Playwright or Selenium code, it works too, without any changes.

Do I need a real app to start?

No, not to write test cases. Generating, reviewing and downloading cases needs only the text. You need the app's link only when you press Run.

What does the confidence score mean?

It shows how sure we are that a result is right. It drops when a step was only partly understood or an element was matched by guesswork. A separate release score is 100 minus the residual risk.

Will it change my tests?

Only if you press Apply on a fix you've reviewed. Assertions, the checks that decide pass or fail, are never touched.

Is my data sent anywhere?

EasyTesting runs on your own machine or server. Nothing leaves it unless you turn on the optional AI helper, which sends the use case text to Anthropic to write the cases.

What do I need to run it?

A computer or server with Node.js 22.13 or newer, and Google Chrome or Microsoft Edge for the tests. There is also a ready-made Docker setup for hosting it for a team. Your testers only need a web browser.

How do I get an account?

If your team already runs EasyTesting, choose Sign in. If it is new for you, choose Get started: the first person creates the admin account and can add everyone else, and a team can also switch on self-service sign-up so people create their own.

Can my team use it?

Yes. Run it on a shared server with the included Docker setup. Each person signs in with their own account and sees only their own work.

Which browsers and apps does it test?

Websites, in Chrome or Edge. Mobile apps are planned but not available yet.

Ready to try it?

New here, get EasyTesting running in about two minutes. Already set up, sign in. You'll need Node.js 22.13 or newer, and Chrome or Edge.
